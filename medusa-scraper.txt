1.3 Medusa's Architecture

HTTP, Workflows, and Modules Layers
Medusa is a Headless eCommerce platform(this mean the front and the back are separated) which means more flexibility and scalability. So storefront, admin dashboards, and others clients
consume Medusa's functionalities through its API routes.

In a common Medusa application, requests go through four layers in the stack. In order of entry, those are:

1. API routes(HTTP) Our API routes are the typical entry point. The Medusa server is based in Express.js, which handles incoming requests. It can also connect to a Redis database that
store the server session data. → Oséa a através de las APIs es como se comunica. 

2. API routes consume workflows that hold the opinionated business logic of your applicaction

3. Modules: Workflows use domain-specific modules for resource management

4. Data store: Modules query the underlying datastore, which is a PostgreSQL database in common cases.


# DATABASE layer

Medusa app injects into each module, including your custom modules, a connection to the configured PostgreSQL database. They read and write data in that database this way.

# THIRDPARTY Integration layer

Services and systems are implemented via infraestructure modules. You can create custom modules.

Commerce Modules

Integrate third-party services relevant for commerce or user facing features. For example, you can integrate Stripe through payment module provider. You can integrate third-party services for custom funcionalities

# Infrastructure Modules

Integrate third-party services and systems that customize Medusa's infrastructure

2.1. Build Custom Features

In the upcoming chapters they will teach you how to build Medusa's custom features, and they will introduce us to the key concepts of the platform.
By following these guides, you will add brands to the Medusa app that you can associate with products.

You need three main frameworks to create custom features in Medusa.

• Module: a package with commerce logic for a single domain. It defines new tables to add to the database, and a class of methods to manage these tables. 
• Workflow: a tool to perform an operation comprising multiple steps with built-in rollback and retry mechanisms.
• API route: a REST endpoint that exposes commerce features to clients, such as the admin dashboard or a storefront. The API route executes a workflow that implements the commerce feature using modules.
